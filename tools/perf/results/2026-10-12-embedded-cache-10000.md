# 10,000-cell embedded routing-cache and recovery validation

Both three-node scenarios completed with all 37 required routing-cache checkpoints, 18 captured startup policies and 14 returned SDK shutdown proofs passing. Every checkpoint reported 32 cached routes, 512 owned cells, 512 occupied slots and 544 total tracked cell records while traversing 10,000 business cells. Final preserving reloads exactly matched 29,489 acknowledged writes in bucket mode and 30,240 in fleet mode. Every cell had been written; all reads checked its counter and 1-KiB payload length. There were no load errors, counter mismatches or verification read retries.

The [structured report](2026-10-12-embedded-cache-10000.json) records the immutable image ID, source hashes, measured snapshots, exact acknowledgement ledgers and returned SDK proofs. Image `cellar-embedded-perf:4db0ba6` was built from `4db0ba656cf30228d5d1ca93008df802c599b889`. The harness captured clean checkout `52519f1`; its production and measuring sources match that image. The report checkout at `0bbb2b1` on merged main also has identical production and measuring sources. The run exited successfully, and its private containers, network and loop directory were independently confirmed absent after cleanup. Raw artifacts remain at `.cellar/perf/embedded-cache-10000-4db0ba6` and in a separately retained archive whose digest is recorded in the structured report.

## Workload and resources

The application embedded `cellar::sdk::Node` and supplied its host/core Tokio runtimes, listeners, authenticated peer clients, signing identities and S3 clients. Each node had 1 CPU, 2 GiB memory and a private 5 GiB ext4 data image. The load generator had 2 CPUs and 2 GiB memory; RustFS had 2 CPUs and 4 GiB memory. All containers shared an 8-CPU Colima VM and backing disk on an Apple M2 Max.

Each scenario used a fresh bucket and 10,000 cells. Transactions incremented persistent counters and overwrote JSON values with changing seeded random ASCII payloads. The requested limits were 512 resident cells, 32 cached routes and 512 requests per script pool; every node startup reported those captured values. Warmup ran for 180 seconds, followed by two 20-second repetitions at each concurrency. Traffic was closed loop and writes were never retried. Percentile ranges span individual repetitions rather than pooled samples.

## Recovery and process control

Bucket mode killed all three processes and discarded their local SQLite and log files. Cold restoration verified all 27,493 acknowledgements existing at that point in 232.8 seconds. Later rolling-write phases added 1,996 acknowledgements; those were checked after handoffs and the final preserving reload.

Fleet mode killed one node, retained its local disk and verified all 28,894 acknowledgements through the two survivors in 322.1 seconds. The observed owner histogram contained only nodes 2 and 3. This checks recovery after losing a process; acknowledgement source is not separately instrumented and fleet durability can fall back to bucket proof.

Both scenarios handed off and restarted each node, verified the ledger after takeover, wrote more, then verified again. The last node stopped with Preserve, restarted alone and read all 10,000 cells as node 3. Final preserving verification took 295.1 seconds in bucket mode and 255.2 seconds in fleet mode.

All 10 handoff stops and four preserving stops returned exit code zero and complete ingress, application-event, cell, log and local-durability proofs. Pending application events and dispatches were zero, neither shutdown budget was exhausted, and both caller-owned executors remained usable after the SDK joined its owned work. Every preserving stop prepared a clean local reload.

## Routing history and validation limits

Required snapshots covered warmup, measurement, recovery, all three rolling write phases and each final preserving reload. All 37 independently parsed snapshots met the 32-route policy and reported exactly 544 tracked records. The [zero-cache run](2026-10-12-embedded-cache-zero-1000.md) separately verified that caching can be disabled. The [earlier 10,000-cell reference](2026-10-12-embedded-10000-reference.md) predates this cache bound and is not evidence for it.

Measured node RSS ranged from 145 to 148 MiB, working set from 194 to 201 MiB, and peak cgroup memory including filesystem cache from 527 to 683 MiB. Measured memory-event counters showed no OOM or memory-limit events. Routing-history reclamation does not discard ownership, alarms or unfinished work; these sampled records and memory readings do not establish a whole-process memory bound.

Raw verification `nodes` means configured scenario width, which remains three when only two survivors or the final node are used. Endpoint selection and observed owners establish those actual topologies.

This is bounded local correctness evidence. Shared VM resources and a single-server RustFS store do not model production infrastructure or establish a performance comparison against the earlier image. Failures occur between write phases. Partitions during writes, ambiguous acknowledgements, independently arriving traffic, hot-cell skew, growing datasets, long soaks and target production fleet sizes remain untested here. The 18 recovery checks plus two initial checks validate counters and payload lengths, not payload digests or every SDK primitive.
