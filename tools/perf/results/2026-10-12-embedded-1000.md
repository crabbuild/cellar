# Embedded SDK fleet validation · 2026-10-12

The application embeds `cellar::sdk::Node` and supplies its host/core runtimes,
listeners, peer authentication, signing identities and object-store clients.
Both three-node scenarios completed with zero write errors, exact acknowledged
counters after recovery, and all 14 graceful shutdown reports passing. The
caller-owned runtimes remained usable after each node joined its work.

The [complete report](2026-10-12-embedded-1000.json) records clean source
`20fb251d7fb239de57bc712775d6349b5dc0a0b5`, the matching image revision label,
source hashes, resource samples, individual measurements and shutdown reports.
The image is
`sha256:f0a6687f441c4ea3212548d3f3680440905840273650a9e342604b38c8c68430`.

## Workload and resources

- 1,000 cells; each transaction increments a persistent counter and overwrites
  a JSON value with a changing 1 KiB payload.
- Closed-loop workers, disjoint cell partitions, rotating ingress and no write
  retries; concurrency 32 and 128, two 20-second measurements each after a
  60-second warmup per scenario.
- Three nodes, each limited to one CPU, 2 GiB RAM and a private 5 GiB ext4 data
  image. Explicit limits allow 512 resident cells per node and 512 requests per
  script pool; rebalance is disabled.
- Apple M2 Max, ARM64 Colima VM with eight CPUs and 16 GiB RAM; all containers
  share the VM and backing disk. The load generator has two CPUs and 2 GiB RAM;
  the single RustFS server has two CPUs and 4 GiB RAM.
- Linux ARM64 release build, Rust 1.98.1, repository `opt-level=s` and fat LTO.
  Stop deadline is 60 seconds.

## Recovery and shutdown

Bucket mode killed all nodes and discarded their local data. Reading all 1,000
cells after restart recovered exactly 126,972 acknowledged writes in 32.5
seconds. Fleet mode killed one node and read all cells through the survivors,
recovering exactly 165,473 acknowledged writes in 12.2 seconds. These timings
measure verification reads, including activation/retry time, after the harness
waited for node health; they are not end-to-end outage durations.

Each scenario then handed off and restarted every node. Every takeover check
and every check following new writes matched the acknowledged counters.
Finally, the last node stopped with Preserve, restarted alone, and recovered
exactly 141,684 writes in bucket mode and 184,270 in fleet mode. The final
verification reads took 14.2 and 14.1 seconds respectively.

All 14 graceful stops returned exit code zero and `NodeOutcome::Stopped`, with
ingress, complete application work, cells, log and local durability drained;
pending events and dispatches were zero. No stop timed out or exhausted its
deadline. All four preserving stops prepared a clean reload. Both caller
runtimes passed a post-join task probe after every stop. No panic appeared in
the run logs, and the harness's containers, network and loop-image directory
were removed after completion.

## Failures found before this run

The [initial admission run](2026-10-12-embedded-admission-failure.json) used the
SDK's default limit of 64 requests per script pool. It failed with 37 HTTP 503
responses at concurrency 128. Root requests keep their admission slots while
nested cell calls settle. The benchmark application now explicitly selects a
finite limit of 512; the SDK default is unchanged. The analysis retains the
failed sample even though the load command raised before adding it to the
successful measurement list.

The [subsequent shutdown run](2026-10-12-embedded-actor-closure-failure.json)
used that limit and passed all measured writes and recovery checks, but a final
handoff exited with code 133 and no shutdown proof. Domain closure raced the
actor's current poll, turning normal cancellation into an invariant panic.
A deterministic regression reproduced the panic before the fix. Production
actor boundaries now refuse closed-domain admission and preserve cancellation
without manufacturing completion events. The current run repeated the original
scenario and completed all final handoffs and preserving reloads. Both earlier
reports remain marked incomplete.

Local gates passed 217 Rust tests across 66 harnesses, eight doc tests, workspace
check and Clippy with all targets/features, formatting, six Python proof/report
tests, and the JavaScript-engine dependency guard across 386 reachable packages.
The externally supplied internal/conformance harnesses were not run.

## Scope

This validates the embedding path and bounded local recovery. Failures occur
between write phases. It does not exercise concurrent ambiguous acknowledgments,
independent arrivals, network partitions, hot-cell skew, data growth, long soaks,
production S3 or a wide fleet. Fleet acknowledgments can fall back to bucket
proof, and the report does not distinguish each acknowledgment's proof source.
See [the harness instructions](../README.md) to reproduce the run with a private
image/cache and fresh local resources.
